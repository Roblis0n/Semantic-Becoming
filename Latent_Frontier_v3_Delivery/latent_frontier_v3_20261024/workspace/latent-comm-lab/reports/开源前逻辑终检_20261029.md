## 已修复的问题

### 编译器作用域绕过

节点可将实际写集合声明为空，掩盖操作副作用。现在声明必须覆盖能力规定的完整写集合，并处于获准作用域。

涉及：src/latent_comm/compiler/pipeline.py。

### 因果世界增量缓存失效

旧值没有方程、噪声与干预上下文。新增 snapshot_scm 快照并自动传播变化；裸 prior_values 元组被拒绝。

涉及：src/latent_comm/mechanisms/h31_grafting/reference.py。

### 版本身份漏检

显式指定 frame 等轴时，只检查 schema/task 存在而不比较。现在这两个身份轴始终逐项比较。

涉及：src/latent_comm/learning/contracts.py。

### 结构分割与记录来源不一致

生成器改版本可能跨 split，同一新组合的倒序会漏过留出；读取器还信任自报 split。现在结构分割不受生成器版本与概念顺序影响，记录绑定分割清单、模板签名及分片内容。新增元数据清单构造方法。

涉及：src/latent_comm/data/splits.py; src/latent_comm/learning/source.py。

### 事务删除忽略草稿

创建后删除或子分支删除父草稿会被判为不存在。删除现在读取当前事务可见状态。

涉及：src/latent_comm/runtime/transactions.py。

### 来源标识检查被当成独立性判断

H44 的不重叠 ID 仅是必要检查，不能证明统计独立。现在要求明确 independence_assumed=True，并在学习调用与文档中区分检查和假设。

涉及：src/latent_comm/mechanisms/h44_dreaming/reference.py。

### 概率比较误报

C12 对浮点概率用精确字典相等，噪声行重排即可产生 1e-16 级误差。现在按既有 1e-9 容差比较概率，缺失的零质量按零处理。

涉及：src/latent_comm/compositions/c12.py。

### 有限例预算被重复使用

H29 源域、目标域及嵌套组合各自重置预算。现在同一次关系检查、组合与问题图共享预算，耗尽时保留 frontier。64 等限额只约束本轮有限工具调用，不限制理论的目标规模。

涉及：src/latent_comm/mechanisms/h29_questions/reference.py。

### 缺失回执留下完成状态

任务回执删除后，sync 仍可能保留旧 done 行且无法重新就绪。现在按现存回执重建状态，缺失回执回到 pending。

涉及：scripts/task_checkpoint.py。

### Windows 与未来命令接口

Linux fcntl 在导入阶段阻断所有内存事务；中文元数据使用默认 GBK；两处学习 CLI 遗漏恢复参数；backend extra 漏 torch。现在按功能报告平台边界，必要读写显式 UTF-8，补齐恢复参数和依赖元数据。

涉及：src/latent_comm/runtime/files.py; src/latent_comm/learning/*/train.py; scripts/*.py; pyproject.toml。

### 压缩包路径别名覆盖

ZIP 校验接受点段、大小写别名、内部冒号及 Windows 自动规范化前的反斜杠路径。现在检查规范路径和原始路径，并拒绝可移植路径冲突。

涉及：scripts/build_release.py。

## 使用变化与保留条件

- H31旧的裸值缓存参数不再被接受。先调用 snapshot_scm，再把快照作为 prior_values；噪声、干预和方程变化自动触发重算。
- H44调用需明确 independence_assumed=True；学习世界记录的 public_task 中对应 holdout_independence_assumed=true。它表达假设，不授予统计独立性证明。
- 未来数据清单需有 split_manifest 与 split_manifest_digest，可由 SplitManifest.dataset_manifest(shards) 构造；结构分割策略版本为 structural-v2。旧清单不能无声地换新分割。
- H29仍采用精确有限域成员比较。0.1×3 与0.3的浮点差异可能保守拒绝等价声明，没有为通过检查而改成模糊相等。
- Windows可以使用内存事务；持久文件事务仍明确需要POSIX锁，未在本机验证Linux持久化或故障恢复。
- 未来训练数据目前只有WorldRecord迭代器与JSONL读取器，尚无分片写入器；不能称为已经跑通的训练数据端到端流水线。此缺口不影响理论提案与本轮有限语义检查。
- 角色对象、键和形状合同仍信任调用方遵守张量来源约定；不声称仅靠类型合同就能证明张量从未混入监督数据。
