# 程序扩展 事务与能力联盟的有限保证

覆盖 H39、H40、H41、H42，补足 F01–F08 未单独展开的组织机制；研究 NOT_RUN。这里主动区分成熟软件原语与候选认知组织贡献。

## 宏展开的保守性 D09

基底语言 L₀ 是有限纯表达式：常数、变量、加法、乘法、let，使用显式环境；不含文件/网络副作用。L₁ 加入有限无环宏定义 μ_i(参数)=p_i，展开函数 lower 做捕获规避替换并按宏依赖递归。宏依赖无环保证递归层数有限，执行另受总步预算限制。

对表达式结构归纳证明 Exec₁(e,η)=Exec₀(lower(e),η)，前提是两边都在声明域完成、纯操作一致、参数绑定卫生。常数和变量直接相等；二元算子由子表达式归纳和同一基底算子得；let 必须先求绑定值，再在同一扩展环境中应用归纳；宏调用按定义替换、重命名绑定变量避免捕获，然后应用无环依赖的归纳。该定理是宏的保守扩展，不意味着更强可计算性。

反例 μ(x)=2(x+1)，误 lower 为 2x+1，x=0 时输出分别 2、1。捕获反例：μ(x)=let y=1 in x+y，调用 μ(y) 且外部 y=2 应为 3，直接替换而让 y 被内层绑定会变 2。若参数表达式有副作用，重复代入也不保调用次数，因此当前纯语言条件不可删。

编码收益需计定义开销：若重复 r 次、原体字节 b、调用字节 c、定义额外开销 d，则净省 (r−1)b−rc−d。它可能为负，不能每抽一个宏都报告压缩。描述长度减少也不必减少展开后的原始步骤；有限预算下快捷硬件原语与可展开宏又是不同对象。当前 `h40_instruction_set/reference.py::lower/execute_base/propose_macro` 实现上述纯标量有限版，候选匹配的字节模型明确，不是全局最优程序合成。

## 事务的条件串行性 D09b

考虑一个进程内单一 VersionedStore 协调实例，所有读写均通过其锁，所有被读取以及将写入的键均列入 read_versions。每次提交在锁内先核对版本，再构造完整候选状态，再用同文件系统原子替换发布。若这些条件成立，可将成功事务按原子发布时刻排序，得到与该顺序一致的串行结果：较晚事务如果读了被早先改变的版本会失败；未失败者读取值仍等于其声明快照。

这个证明不覆盖多个独立 store 实例/进程、绕过 API 的文件写入、分布式网络故障或真实外部副作用。只检查 write-write 冲突不够：A 读 x 写 y，B 改 x，即便写集合不交，A 也需因 read 版本过期而中止。事务原子性不证明里面的新概念语义正确，只保证版本成组可见。

恢复日志记录 before/after 哈希。重启时可见状态等于 before 则 abort，等于 after 则补 commit；都不等则报告 JournalCorrupt。该有限模型需在接纳新写入前完成未决 prepare 的恢复，并依赖底层 fsync/rename 语义；不是分布式共识协议证明。rollback 是另一次高版本补偿提交，不把版本时钟倒退；若已有更新则禁止覆盖。已发消息、付款不可纳入这种回滚。

`h39_transactions/reference.py::VersionedStore.commit/recover/rollback` 的类注释明确 single in-process coordinator，RLock 不提供跨进程互斥。D02 不把本地注入中断测试扩成真实崩溃/分布式容错结果。

## Shapley 恒等式与未知价值 D09c

有限玩家集 N，完整实值函数 v:2^N→R。对均匀随机排列 π，P_i(π) 为 i 之前的玩家，定义 φ_i=E_π[v(P_i∪{i})−v(P_i)]。固定子集 S 作为前驱的排列数为 |S|!(n−|S|−1)!，除 n! 得标准系数。

每个排列上的边际和按链望远镜相消，Σ_i[v(P_i∪{i})−v(P_i)]=v(N)−v(∅)；取期望得到效率恒等式。若 i 为 dummy，即对所有 S 均有 v(S∪{i})=v(S)，逐项为 0。交换对称玩家的排列建立一一映射，故对称者份额相等。

两人 v(∅)=v({A})=v({B})=0,v({A,B})=1，则各 1/2。若错误把未知 v({A}) 当 0，可把真实独占贡献误当协同。若 v(∅)=2,v(A)=2,v(B)=2,v(AB)=3，贡献总和是 1 而不是 3。精确分摊依赖完整 v；采样仅近似排列平均，不证明公平、因果贡献、激励相容或货币价值。

重复来源纠正属于价值函数定义，不是 Shapley 自动去重。若两个 agent 同引 e，可以定义唯一来源集合价值，也可定义任务执行互补价值，二者通常不同；不得把 source 数量相加叫概率。H41 `exact_shapley` 缺表项返回 UndefinedValue，`sampled_shapley` 报告样本与方差，`capability_plan` 检查前置类型和内部资源。exact 的 8 玩家源码上限不覆盖本轮 64-case 政策：2^n 必须在预算内，不能执行 n=8 的 256 表项样例。

## 共演化终止与开放性的区别 D09d

H42 的任务/协议候选来自固定有限变异语法，每次候选消耗共享预算，并按结构签名去重。在给定步数 B、世界数 W、种群数 P 的边界下，最多 B 次被计费候选就停止；archive 存在并不意味着出现过新的有效能力。结构签名只对声明编码判重，不证明所有语义等价程序被合并。

当前 `h42_ecology/reference.py::evolve` 返回的是有限表达能力候选、缺少操作与谱系，不运行神经模型。“expressible_candidate” 不能写成实测 competence。`inverse` 标志使 offset 符号反转，不是对所有 conditional 程序求函数逆：当分段阈值造成非单射/非满射，减回 offset 未必恢复原输入。例 f(x)=x+1 当 x≥0，否则 x；对 y=.5，按同阈值减一得 −.5，但 f(−.5)=−.5≠.5。因此外文标签不授予数学逆的定理。

若有限可达结构集合为 R，去重 archive 的严格增长至多 |R| 次。要谈长期开放式创新，必须另让语法、对象类型或环境发生扩张，并声明迁移、权限和意义评价；不是把预算去掉形成无限循环。该困难是 V 的假设链，不是删掉生态方向的理由。
