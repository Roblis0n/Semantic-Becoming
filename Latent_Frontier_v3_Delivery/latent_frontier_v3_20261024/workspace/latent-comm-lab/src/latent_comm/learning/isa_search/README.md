# L09: macro structure search and exact-base anchored fast execution

NOT_RUN. fast_macro binds W09 sender macro and receiver caller_argument. The restricted W09 family is explicitly arg × multiplier, then the public caller continuation adds 1. A typed macro is lowered hygienically into immutable H40 base ISA; the exact tensor base interpreter provides a stopped target. The fast implementation is a four-term polynomial in argument and the declared multiplier, not a generic MLP. Parameter owner fast_macro_coefficients is trained with per-valid-anchor squared error. Actual task answers remain supervisor-only and are not used to generate the macro.

W09 has only one legal lexical binding, so it does not pretend to train a multi-class selector from constant labels. typed_binding is a separately declared extension: receiver binding_features[B,C,F] and binding_valid[B,C], supervisor binding_index. Scalar type filtering happens before the selector; invalid selected targets are rejected. The exact macro still uses its declared lexical argument, and binding CE is separately normalized. This extension requires its own W13-projected manifest.

select_macro_structure performs the real H40 repeated-subtree search and accounts actual encoded definition plus call costs. It returns a positive byte-saving proposal or the specific NoCompressionGain failure, not a fake differentiable description penalty. Lowering, discrete choice, ISA version installation and recompilation are outside continuous gradients. Every nested finite reference call shares the aggregate budget; expansion budgets cannot be minted by helper calls.

Freeze table: fast_macro_coefficients for the ordinary phase; add binding_selector only for typed_binding. Exact base semantics, macro source and base ISA version are immutable. No base model exists in this adapter family. The graph is typed macro → hygienic lowering → exact base target (stop) versus public arguments → monomial features → learned coefficients; only the second side trains. Source versions pin ISA/ontology/evidence and every training run must bind actual manifests.

Every batch is physically split into RoleBatch(sender), RoleBatch(receiver), and SupervisionBatch; only losses receive supervision.
